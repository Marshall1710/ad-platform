# Качество интерфейсов Next.js и React

Применяйте к apps/cabinet и apps/auction в пределах текущей задачи. Это рабочие интерфейсы для настройки кампаний и проверки аукциона: визуальная ясность действий и данных важнее декоративной оригинальности.

## Перед реализацией

- Определите главную задачу пользователя на экране, обязательные поля, состояния и последствия действия. Используйте реальные термины проекта: кампания, креатив, ставка, таргеты, участие, победа, показ, клик, расход.
- Продумайте компактную систему цвета, шрифта, отступов и иерархии. Для форм и таблиц различайте подписи, значения, подсказки, ошибки и статусы. Не превращайте кабинет в рекламный лендинг.
- Сверьте новые элементы с уже существующим интерфейсом. Новая страница должна выглядеть частью того же приложения.

## Реализация

- Оставляйте серверные компоненты Next.js серверными, когда интерактивность браузера не нужна. Добавляйте клиентские компоненты для конкретных интерактивных участков, а не для всей страницы без причины.
- Держите данные, доступные только серверу, на сервере. Скрытие кнопки по роли не заменяет серверную проверку полномочий.
- Для форм обеспечьте понятные метки, ошибки возле поля и общий результат операции. Сохраняйте введённые данные после ошибки, если это безопасно. Показывайте состояния загрузки, пустого результата, успешного действия и недоступности сервиса там, где они возможны.
- Используйте семантические элементы HTML, управление клавиатурой и видимый фокус. Проверяйте контраст и читаемость на узком экране. Не передавайте смысл только цветом.
- Разделяйте компоненты по ответственности, когда это облегчает чтение, повторное использование или тестирование. Не стройте библиотеку абстракций для одного экрана.
- Параллелизуйте независимые запросы, если это снижает ожидание и не ломает причинный порядок. Не создавайте цепочки запросов без зависимости.
- Следите за объёмом клиентского кода. Тяжёлые компоненты загружайте по требованию, если это оправдано наблюдаемой стоимостью. Не добавляйте memoization, кэш или динамический импорт без понятного выигрыша; проверяйте результат измерением.
- Не переписывайте импорты библиотек по универсальному правилу: учитывайте возможности текущего Next.js и сборщика.

## Проверка

- Проверяйте правила преобразования данных отдельно от UI, интерактивные состояния через React Testing Library, критичный путь пользователя через Playwright — в пределах согласованной задачи и конституции.
- После изменения интерфейса смотрите страницу в браузере: переполнение, состояние ошибок, табуляция, доступность кнопок и фактический текст. Успешная сборка не подтверждает удобство экрана.
