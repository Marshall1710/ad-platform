# HTTP-контракт кабинета для кампаний

## Область доступа

Используется действующая сессия кабинета. Рекламодатель обращается к своим кампаниям. Администратор запрашивает список пользователей, выбирает владельца и действует по тем же правилам кампаний. Запросы, меняющие данные, допускаются с настроенного доверенного origin. Проверка относится также к выдаче изображения.

## Кампании

| Метод и путь | Данные и результат |
| --- | --- |
| `GET /api/admin/users` | Только для администратора. Email, роль и внутренний идентификатор для выбора учётной записи. В кабинете пользователю показываются email и роль. |
| `GET /api/campaigns` | Рекламодатель получает свои кампании. Для администратора параметр `owner_id` выбирает одного рекламодателя. Если кампаний нет, результат — пустой список. |
| `POST /api/campaigns` | Создаёт кампанию в `created`. Для рекламодателя владелец берётся из сессии. Администратор передаёт `owner_id` существующего рекламодателя. Успех — `201` и данные кампании. |
| `GET /api/campaigns/{id}` | Данные доступной кампании и метаданные креатива при наличии. |
| `PATCH /api/campaigns/{id}` | Передаются изменяемые настройки. Пропущенные поля остаются прежними. При нарушении ограничения по статусу изменения отклоняются целиком. |
| `POST /api/campaigns/{id}/activate` | Проверяет статус и готовность, сохраняет `active`, возвращает обновлённую кампанию. |
| `POST /api/campaigns/{id}/pause` | Из `active` сохраняет `paused` и возвращает обновлённую кампанию. |
| `DELETE /api/campaigns/{id}` | Удаляет из `created` или `paused`. Успех — `204`. Удалённая кампания при новом запросе недоступна. |

Поля настройки кампании — `traffic_category`, `payment_model`, `bid_usd`, `countries` и `devices`. Сумма ставки передаётся в USD десятичной строкой. Списки стран и устройств передаются массивами. Пустой массив снимает ограничение. Статус и владелец устанавливаются через операции, перечисленные выше. Данные кампании включают `campaign_id`, `owner_id`, `status`, фиксированные размеры и текущие настройки.

## Креатив

| Метод и путь | Данные и результат |
| --- | --- |
| `POST /api/campaigns/{id}/creative` | Добавление первого креатива. Форма `multipart/form-data` с полями `image`, `click_url` и необязательным `name`. Успех — `201`. |
| `PATCH /api/campaigns/{id}/creative` | Та же форма для изменения одного или нескольких полей имеющегося креатива. Переданный файл заменяет изображение. Пустое название очищает его. Пропущенные поля сохраняются. |
| `DELETE /api/campaigns/{id}/creative` | Удаление креатива у неактивной кампании. Успех — `204`. |
| `GET /api/campaigns/{id}/creative/image` | Даёт уполномоченному пользователю JPEG или PNG с проверенным MIME. Изображение выдаётся с `Cache-Control: private, no-store`. |

Операции записи креатива разрешены в `created` и `paused`. Максимальный размер входного файла — 1 МиБ. Предел всего тела запроса — 2 МиБ, включая рамки формы и остальные поля. Лимит тела проверяется по реально прочитанным байтам. Сервер проверяет и декодирует файл прежде, чем сохранить его. Ссылка проверяется разбором URL без запроса к целевому адресу.

## Ошибки

| Статус | Результат |
| --- | --- |
| `400` | Неверные данные или формат. При исправимой ошибке ответ указывает относящееся к ней поле. |
| `401` | Нужна действующая сессия. |
| `403` | Роли запрещена операция либо отклонён origin запроса. |
| `404` | Кампания или креатив не найдены либо недоступны этому пользователю. Это же ответ на повторное удаление уже удалённой кампании. |
| `409` | Конфликт с текущим состоянием, например повторный запрос на паузу или добавление второго креатива. |
| `413` | Превышен лимит входного файла или тела формы. |
| `500` | Сохранение не выполнено. Ответ содержит понятное сообщение без внутренних сведений о базе. |

Успешное чтение и изменение возвращают `200`, если выше не указан другой статус. Ошибки операций не меняют состояние кампании.
