# Модель данных кабинета

## Кампания

| Поле | Правило |
| --- | --- |
| `campaign_id` | Постоянный UUID, присваивается при создании и сохраняется после удаления. |
| `owner_id` | Идентификатор существующего рекламодателя из таблицы `"user"`. Владелец задаётся при создании. |
| `status` | `created`, `active` или `paused`. Начальный статус — `created`. |
| Формат | Фиксированный размер 300×250. |
| Категория трафика | Отсутствует, `adult` или `mainstream`. |
| Модель оплаты | Отсутствует, `CPC` или `CPM`. |
| Ставка | Может отсутствовать у неактивной кампании. Хранится целым числом от 1 до 10 000 в тысячных USD. |
| Страны и устройства | Списки допустимых значений из FR-005. По умолчанию пусты. |
| `deleted_at` | Пустое значение у доступной для управления кампании. Время удаления сохраняет постоянный идентификатор и связь с владельцем для будущих отчётов. |

При чтении для управления исключаются удалённые записи. Список кампаний выбирается по владельцу. Постоянный идентификатор отделён от редактируемых настроек.

## Креатив

| Поле | Правило |
| --- | --- |
| `campaign_id` | Первичный и внешний ключ. Один креатив на кампанию, без отдельного выбора между креативами. |
| Название | Необязательный текст. Пустое значение допустимо. |
| Изображение | Проверенные байты в `bytea` и тип `image/jpeg` или `image/png`. Размеры 300×250, до 1 048 576 байт включительно до сохранения. |
| Ссылка | Обязательный абсолютный URL с `http` или `https`. |

## Переходы и сохранение

- Создание новой кампании сохраняет `created`, владельца и идентификатор даже при пустых настройках.
- При включении из `created` или `paused` проверяются категория, модель, сумма и наличие креатива. При успехе сохраняется `active`. Пустое название креатива и пустые таргеты допустимы.
- Пауза переводит `active` в `paused`. В `active` доступны изменения ставки и таргетов. При изменении ставки требуется новое допустимое значение.
- Добавление, изменение, замена и удаление креатива разрешены в `created` и `paused`.
- Удаление разрешено в `created` и `paused`. В транзакции проставляется `deleted_at` и снимается креатив. Сохраняется запись кампании с владельцем.
- Проверка состояния и запись выполняются под блокировкой строки кампании в одной транзакции. Состояние проверяется в момент записи. Роль и владелец проверяются на сервере при каждой операции.
- Миграция `002_campaigns` применяется после `001_auth` с записью версии в `schema_migrations`. Проверяются установка на чистую базу, обновление существующей базы и повторный запуск миграций.
