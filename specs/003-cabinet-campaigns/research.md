# Решения для реализации кабинета

## Сессия и проверка прав

**Решение** — использовать действующие сессии Better Auth и общий серверный слой для страниц и обработчиков HTTP. Любая операция читает сессию. Запросы к кампании и к её изображению проверяют права на одном уровне. Для запросов браузера, меняющих данные, используется список доверенных origin из настроек входа, включая разрешённый loopback-алиас.

**Обоснование** — `apps/cabinet/src/lib/auth.ts` уже предоставляет сессию и пул PostgreSQL. Правила остаются едиными при открытии страницы и прямом обращении к API. Существующая регистрация, вход и выход сохраняются.

**Альтернатива** — отдельный механизм сессий или проверки только в интерфейсе. Первый дублирует существующий вход, вторая оставляет прямые операции без проверки владельца.

## Данные и удаление

**Решение** — хранить кампанию и не более одного креатива в PostgreSQL кабинета. Ставку хранить целым числом тысячных USD. При удалении сохранить запись кампании со временем удаления и владельцем. В одной транзакции скрыть кампанию из управления и удалить её креатив. Все операции, зависящие от статуса или текущего креатива, синхронизировать блокировкой строки кампании.

**Обоснование** — сохраняется точная ставка и связь для будущих отчётов. Удаление и смена статуса видны согласованно, включая параллельные действия владельца и администратора. Текущий `apps/cabinet/scripts/migrate.mjs` применяет только `001_auth`. Нужно добавить упорядоченное применение `002_campaigns` под существующей блокировкой миграций.

**Альтернатива** — удалить кампанию физически и перенести идентификатор и владельца в отдельную таблицу истории. Для этого среза такая таблица добавляет второй путь поиска связи.

## Изображение креатива

**Решение** — ограничивать размер тела запроса до разбора формы, проверять размер файла, распознанный формат и размеры изображения. Использовать полное декодирование с проверкой повреждений. Для реализации предлагается объявить `sharp@0.35.5` прямой зависимостью кабинета после согласования. Сохранять проверенное изображение в `bytea`. Выдавать его с исходным типом JPEG или PNG через защищённый маршрут кампании.

**Обоснование** — `sharp@0.35.5` уже есть в lockfile как зависимость Next.js. Локальная проверка подтвердила, что эта версия декодирует JPEG и PNG и обнаруживает обрезанные файлы, заголовки которых ещё читаются. В lockfile есть платформенные пакеты для используемого Alpine. Прямое объявление даёт кабинету явную зависимость. PostgreSQL уже подключён и использует постоянный том.

**Альтернативы** — проверять заголовок файла самостоятельно или хранить файлы отдельно от PostgreSQL. Заголовок не подтверждает целостность. Отдельное хранилище потребует согласовать запись и удаление между двумя системами.

## Проверка на локальном стенде

**Решение** — Vitest и React Testing Library для правил и компонентов. PostgreSQL Testcontainers для миграций, операций и проверок доступа через HTTP-обработчики. Playwright для пользовательского пути против контейнеров `cabinet-db` и `cabinet`.

**Обоснование** — проект уже использует эти инструменты. Общая проверка `npm run test:smoke` включает проверку базы DSP. Целевой сценарий Playwright запускается отдельно, чтобы кабинет можно было принять первым. Docker Engine 29.9.2 ответил на запрос версии с разрешённым доступом к Docker API. Проверки со стендом пройдут после реализации.
