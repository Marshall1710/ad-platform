# Data Model: регистрация и вход

Владелец всех сущностей — сервис кабинета и его PostgreSQL. БД DSP не используется.

| Сущность | Поля и ограничения | Связь |
| --- | --- | --- |
| `user` | Внутренний ID, email (уникальный в нормализованном виде), служебное имя библиотеки, `role` = `advertiser` или `admin`, даты создания/обновления | Один пользователь имеет несколько сессий и один credentials-account |
| `account` | ID, идентификатор провайдера `credential`, ID пользователя, хеш пароля; открытый пароль не хранится | Принадлежит пользователю; структура Better Auth также допускает другой провайдер позднее |
| `session` | ID, непрозрачный токен, ID пользователя, `expiresAt`, служебные метаданные | Принадлежит пользователю; удаляется при выходе, истекает через 24 часа без продления |
| `verification` | Служебная таблица, требуемая схемой Better Auth | В текущем сценарии подтверждение email не включено |
| `schema_migrations` | Имя применённой миграции и дата | Учитывает применение версионированных SQL-файлов |

## Инварианты

- Публичный путь создаёт только `advertiser`; `role` не принимается из пользовательского ввода.
- Команда администратора использует серверную конфигурацию для создания `admin` без сессии и не предоставляет публичный API этой операции.
- Email нормализуется одинаково для регистрации, входа и команды администратора: внешние пробелы удаляются, регистр приводится к нижнему.
- Уникальность email защищена ограничением БД, включая конкурентные запросы.
- Пароль доступен только при вводе и проверке; в БД хранится хеш.
- Сессия недействительна после выхода или `expiresAt`, даже если у браузера осталась cookie.
- В представлении показываются только email и роль текущего пользователя.
