# Контракты первого среза доступа

## UI

| Путь | Доступ | Поведение |
| --- | --- | --- |
| `/` | Все | Стартовая страница кабинета со ссылками «Регистрация» и «Вход»; сохраняет заголовок «Кабинет рекламодателя». |
| `/register` | Все | Форма email/пароль, ошибки возле полей и общий результат; при успехе переход в `/cabinet`. |
| `/login` | Все | Та же пара полей; неверные email/пароль дают одно сообщение, при успехе переход в `/cabinet`. |
| `/cabinet` | Только действующая сессия | Показывает собственные email и роль, кнопку «Выйти»; при отсутствии/истечении сессии перенаправляет на `/login`. |

## HTTP

Better Auth монтируется под `/api/auth/[...all]` и обеспечивает `POST /api/auth/sign-up/email`, `POST /api/auth/sign-in/email`, `POST /api/auth/sign-out`, `GET /api/auth/get-session`. Серверная обёртка нормализует email в запросах регистрации и входа, а при регистрации заполняет обязательное внутреннее поле `name` нормализованным email. Форма запрашивает у пользователя только email и пароль. Публичный входной `role` игнорируется библиотекой (`input: false`). Публичная HTTP-обёртка допускает только четыре перечисленных маршрута Better Auth; остальные маршруты возвращают 404. Нет конечной точки для списка пользователей или выдачи admin. Для локального стенда разрешены оба loopback-адреса, `127.0.0.1` и `localhost`, на настроенном порту кабинета; произвольные Origin не разрешены. Ответ 403 об отклонённом адресе не показывается как занятый email или неверный пароль. Ответ 429 показывается как временное ограничение числа попыток.

| Запрос/состояние | Ожидаемый результат |
| --- | --- |
| Корректная регистрация | Запись `advertiser` и действующая cookie сессии. |
| Повтор email | Отказ без создания второй записи. |
| Неверные реквизиты входа | Отказ без сессии; UI показывает общий текст. |
| Выход с действующей сессией | Сервер удаляет текущую сессию; UI возвращается на вход. |
| Прямой запрос `/cabinet` без действующей сессии | Редирект на `/login`; email и роль не выдаются. |
| Публичная регистрация с `role: admin` | Создаётся `advertiser`; admin-роли нет. |

## CLI

Команда `npm run admin:create` запускается оператором в контейнере кабинета, запрашивает email и пароль интерактивно и создаёт только `admin`. Пароль не передаётся в аргументах процесса и не выводится на экран. При занятом email команда завершается с ошибкой без изменения существующего пользователя. Команда не доступна через HTTP.
