# Решения по подготовке каркаса

- **Структура**: три развёртываемых приложения в apps/cabinet, apps/auction, apps/dsp. Так каталог соответствует согласованной архитектуре и каждому Docker-образу.
- **Node-зависимости**: npm workspaces для двух Next.js-приложений и один корневой lockfile. На машине уже доступны Node.js 22 и npm 10. Next.js 16.4.5 совместим с React 19.3.1 по peer dependencies npm.
- **Go**: локально установлен Go 1.27.3; DSP собирается внутри Docker из той же ветки 1.27.
- **Проверка запуска**: Playwright открывает оба интерфейса и проверяет HTTP-ответ DSP. Отдельный скрипт вызывает pg_isready внутри двух контейнеров PostgreSQL. Проверка наблюдает все пять частей системы, а не повторяет конфигурацию.
- **Базы**: отдельные контейнеры и тома. Схемы и драйверы не добавляются до спецификаций, которым они нужны.
- **Библиотеки предметной логики**: авторизация, SQL-драйверы, миграции и Testcontainers добавляются вместе с соответствующей логикой и тестами. Раннее закрепление этих решений не требуется для локального запуска каркаса.
- **Альтернативы**: отдельные lockfile у Next-приложений усложнили бы синхронизацию версий; запуск всех проверок только из контейнера усложнил бы будущие Testcontainers-тесты Go.
